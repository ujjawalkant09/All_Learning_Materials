# 22 · Project — Dynamic Tool Agent

Agents and their tools' **source code** are stored in SQLite and turned into a running agent at runtime,
so you can add a tool without redeploying.

| File | Purpose |
|---|---|
| `01_db_schema_design.ipynb` | full schema design (agents, tools, links, execution logs) → creates `sample.db`. Runs offline |
| `02_dynamic_tool_agent.ipynb` | simplified implementation: seed `agent.db`, load the rows, build the agent |
| `agent.db` / `sample.db` | generated by the notebooks; safe to delete and recreate |

**Concepts used:** tools [09] · `create_agent` [10] · `StructuredTool.from_function`

**Why it's built this way:** tools come from data, not from code you import, so `@tool` can't be used.
`StructuredTool.from_function` builds a tool from any function and lets each one have its own name and
description. ⚠️ `exec()` runs code from the DB, which is fine for local learning; a real system needs a sandbox.
